# ЗАВДАННЯ

## Застосунок

Drive2U — мобільний сервіс замовлення таксі. Пасажир вибирає
точки подачі та призначення на мапі, отримує попередню вартість
і створює замовлення. Водій приймає замовлення та виконує поїздку.
Застосунок забезпечує керування статусами, сповіщення про зміни
й доступ до історії поїздок.

Довгострокова мета — створити надійний сервіс міських перевезень
із прозорим розрахунком вартості, зручним інтерфейсом і захищеним
обробленням даних пасажирів та водіїв.

## Цільові користувачі

- Пасажири — замовляють поїздки та відстежують їх виконання.
- Водії — отримують і виконують замовлення.
- Адміністратори — керують доступом водіїв, тарифами,
  зверненнями та роботою сервісу.

## Функціональні можливості

- Реєстрація, авторизація та керування профілем.
- Профілі водіїв і транспортних засобів.
- Мапа, пошук адрес і вибір точок поїздки.
- Визначення поточного місцеперебування за згодою користувача.
- Побудова автомобільного маршруту та визначення його відстані.
- Серверний розрахунок попередньої вартості.
- Створення, прийняття, виконання та скасування замовлень.
- Оновлення статусів у реальному часі.
- Історія поїздок і деталізація вартості.
- Подальший розвиток: відстеження водія, автоматичний підбір,
  безготівкова оплата, рейтинги та адміністративний інтерфейс.

Детальні вимоги: [docs/app-requirements.md](docs/app-requirements.md).

## Технологічний стек

- Мобільний клієнт: React Native, Expo, TypeScript.
- Сервер: ASP.NET Core Web API, C#.
- Доступ до даних: Entity Framework Core.
- Початкова база даних: SQLite.
- Авторизація: ASP.NET Core Identity.
- Оновлення в реальному часі: SignalR.
- Серверні тести: xUnit.
- Клієнтські тести: Jest, React Native Testing Library.
- Мапи, геокодування та маршрутизація: зовнішні сервіси,
  інтегровані через окремі адаптери.
- Середовище розробки: VS Code з OpenAI Codex.

Постачальники картографічних сервісів і версії залежностей
фіксуються архітектурними рішеннями після перевірки сумісності,
умов використання, вартості та покриття.

## Агентне середовище

VS Code з OpenAI Codex, авторизація через ChatGPT Plus.

Агент працює з кодом, документацією, git, перевірками
та визначеними MCP-інструментами. Проєктні інструкції
зберігаються в AGENTS.md. Повторювані процедури оформлюються
як skills, контроль операцій — через дозволи, ізоляцію та hooks.

Можливості конкретної версії інструмента перевіряються перед
впровадженням відповідної інтеграції.

## Мета agent harness

Забезпечувати контрольовану й відтворювану допомогу агентів
протягом життєвого циклу Drive2U: від проєктування до реалізації,
тестування, супроводу та розвитку.

Harness має надавати актуальний контекст, формалізовані процедури,
контроль доступу та докази виконаних перевірок.
Відповідальність за архітектуру, приймання змін і випуски
залишається за розробником.

## Цільові задачі агентів

1. Реалізація погоджених функцій мобільного клієнта та API.
2. Створення й виконання тестів бізнес-правил та інтеграцій.
3. Рев’ю безпеки, конкурентного доступу й архітектурних обмежень.
4. Підтримка документації та бази знань відповідно до змін.
5. Відтворення помилок, аналіз причин і перевірка виправлень.

Детальні вимоги: [docs/harness-requirements.md](docs/harness-requirements.md).

## Репозиторії

- drive2u — код клієнта й сервера, документація, тести,
  конфігурація harness, skills, hooks і MCP-конектор.
- drive2u-knowledge — окремий Obsidian vault із вимогами,
  архітектурними рішеннями, глосарієм і знаннями про систему.

Агентний доступ до vault здійснюється через визначений
MCP-конектор. Прямий доступ до файлів vault обмежується
налаштуваннями середовища.
