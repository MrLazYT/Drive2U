# Послідовна оркестрація Drive2U

Координатор запускає окремих subagents через доступний механізм collaboration: Planner → Coder → Reviewer. Наступну роль запускають лише після завершення попередньої та перевірки handoff. Конфігурація Codex не змінюється; додаткові рольові конфігурації не потрібні. Markdown-інструкції ролей є контекстом, а не технічною ізоляцією доступу. Агенти мають спільний workspace; координатор забезпечує послідовність запису.

1. Зафіксувати task, початковий SHA, status, дозволи та джерела.
2. Передати Planner task і релевантні джерела. Зберегти planner-handoff.json за handoff.schema.json.
3. Передати Coder task, план та обмеження. Він реалізує, виконує перевірки й завершує локальний сервер.
4. Передати Reviewer task, handoffs і конкретний diff. Reviewer застосовує drive2u-review, не змінює предмет рев’ю. За доказових дефектів повернути Coder, потім повторити Reviewer.
5. Після приймання синхронізувати знання через MCP, перевірити індекс, commit/push дозволених файлів.

Фіксувати події в transcript.md під час виконання; скорочені повідомлення позначати. Не записувати прихованих міркувань. Якщо subagents недоступні, зберегти handoff для окремої сесії та зупинитися перед наступною роллю. Приклад фактичного запуску: docs/orchestration/backend-fare/.
